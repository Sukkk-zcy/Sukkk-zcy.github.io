## 前言

日常开发中，我们习惯用 Arduino IDE 或 PlatformIO 一键编译烧录。但在很多场景下，我们需要一种更"底层"、更通用的方式操作 ESP32 的 Flash：

- 手头只有别人编译好的 **bin 固件包**，需要手动烧录；
- 想**备份原厂固件**，或者分析设备里到底刷了什么；
- 批量生产时需要把多个固件**合并成一个文件**，一次烧录完成。

这时候，乐鑫官方出品的 **Flash Download Tools**（图形化烧录工具）就是最趁手的工具。它是 Windows 下的绿色软件，解压即用，支持 ESP32 全系列芯片，无需安装任何开发环境。

本文从实战出发，完整介绍它的三大功能：**烧录固件（Write）**、**提取固件（Read）**、**合并固件（CombineBin）**。

| 系列   | 芯片                                                       |

| RISC-V | ESP32-C2、ESP32-C3、ESP32-C5、ESP32-C6、ESP32-H2、ESP32-P4 |

## 第一步：进入下载模式

烧录和读取都要求芯片处于 **下载模式（Download Mode）**，此时芯片不执行用户程序，而是通过 UART 与电脑通信。

> 大部分开发板（NodeMCU、ESP32-DevKitC、ESP32-S3-DevKitC 等）自带 USB 转串口芯片（CP2102/CH340 等），插上 USB 线即可；如果是裸模组，需要外接 USB-TTL 转换器。

进入下载模式的经典方法：

1. 将模块通过 USB 线（或 USB-TTL）连接电脑；
2. **按住 BOOT 按键（GPIO0 拉低）不放**；
3. **点按一下 RST 按键**（复位）；
4. **松开 BOOT 按键**。

此时芯片就停留在下载模式。如果开发板没有按键，也可以在复位瞬间把 GPIO0 接地。

> 如果烧录过程中提示 "Failed to connect to ESP32"，多半是没进入下载模式，或者 COM 口选错了。部分开发板支持 USB 一键进入下载模式（如 ESP32-S3 原生 USB），也可以直接在工具里选择对应的端口后点 START 试试。

## 二、烧录固件（Write）

### 2.1 启动工具

双击运行 `flash_download_tool_3.9.7_64.exe`，弹出启动对话框：

```
ChipType:    ESP32        ← 选择芯片型号
WorkMode:    Develop      ← 开发模式
LoadMode:    UART         ← 通过串口下载
```

- **ChipType**：按实际芯片选择，ESP32 / ESP32-S3 / ESP32-C3 等；
- **WorkMode**：一般选 **Develop**（开发模式），生产批量可选手动配置；
- **LoadMode**：日常串口烧录选 **UART**。

点击 **OK** 进入主界面。

### 2.2 选择固件与地址

烧录的核心就是：**把 bin 文件放到对应的 Flash 地址**。地址不对，芯片可能无法启动。

以经典 **ESP32（Arduino 框架，4MB Flash）** 为例，典型地址映射：

| Flash 地址 | 内容             | 说明             |
| ---------- | ---------------- | ---------------- |
| `0x1000`   | `bootloader.bin` | 二级引导程序     |
| `0x8000`   | `partitions.bin` | 分区表           |
| `0xe000`   | `boot_app0.bin`  | OTA 启动辅助程序 |
| `0x10000`  | `firmware.bin`   | 用户应用程序     |

> 如果是 ESP-IDF 编译的工程，`build` 目录下会生成 `bootloader.bin`、`partition-table.bin`、`xxx.bin`；PlatformIO 在 `.pio/build/<env>/` 下也有这些文件。Arduino IDE 导出二进制时同样会列出地址。

**ESP32-S3 / C3 等新芯片地址略有不同**（bootloader 在 `0x0`，分区表在 `0x8000`，应用在 `0x10000`），请以官方文档或编译输出为准。

### 2.3 配置 SPI 参数并烧录

在 `Download Path Config` 表格中，每一行填写：

1. **固件路径**：点击右侧 `...` 选择 bin 文件；
2. **Flash 地址**：填写对应地址（如 `0x1000`）；
3. 勾选该行左侧的复选框，使其生效。

然后设置：

- **SPI SPEED**：一般选 `40MHz`（ESP32-S3/C3 常用 80MHz，按模块标注选择）；
- **SPI MODE**：常用 `DIO` / `QIO`（按固件编译参数选择）；
- **DoNotChgBin**：勾选后**按 bin 文件原始内容烧录**，不做任何修改；不勾选则工具会按界面的 SPI SPEED / SPI MODE 重新改写 bin 头部再烧录。建议勾选，保持固件原样。

确认 COM 口和波特率（默认 460800 即可，不稳定可降到 230400 / 115200），点击 **START**，开始烧录：

```
等待上电同步...
正在擦除/写入...
FINISH  ✔
```

出现 **FINISH** 即烧录成功。之后按一下开发板 RST 复位，设备即可运行新固件。

### 2.4 先擦除再烧录（重要）

从旧固件升级、或设备之前刷过其他系统（如 AT 固件、MicroPython、陌生固件）时，建议**先整体擦除 Flash** 再烧录，避免旧数据残留导致启动异常：

在工具栏切换到 **Erase** 标签 → 选择 COM 口 → 点击 **ERASE**，等待擦除完成，再回到烧录界面烧录固件。

## 三、提取固件（Read）

提取固件的典型场景：

- 备份**原厂固件**，防止刷坏后无法恢复；
- 分析设备当前运行的固件内容；
- 从"半砖"设备里抢救分区数据。

操作步骤：

1. 进入下载模式（同上）；
2. 在主界面切换到 **ReadFlash** 标签；
3. 填写以下参数：
   - **起始地址（Start Address）**：如 `0x0000`；
   - **长度（Size）**：要读取的字节数，单位可以是字节、KB、MB。经典 4MB Flash 全量读取填 `0x400000`（即 4MB）；
   - **保存文件**：点击 `...` 选择输出 bin 文件的路径和文件名；
4. 选择 COM 口，点击 **START**。

工具会把指定地址区间的内容逐段读出来，写入本地 bin 文件：

```
ReadFlash 完成 → 生成 backup_4m.bin
```

### 提取出的 bin 如何用？

- 全量提取的 bin（从 `0x0` 开始）可以直接**整体烧录回去**（起始地址填 `0x0`，且确保 Flash 大小一致），相当于完整还原；
- 提取的固件可以交给**合并工具**重新打包，或交给反汇编/分析工具（如 `binwalk`）查看内容；
- 结合偏移地址，也可以只提取某个分区（比如只读 `0x10000` 起 1MB 的 app 分区）。

> 注意：读取的 bin 体积等于"长度"指定的字节数，Flash 中未写入的区域读出来是 `0xFF`。

## 四、合并固件（CombineBin）

多文件固件（bootloader + 分区表 + 应用）逐个烧录比较麻烦，尤其是**批量生产**或**发给别人烧录**时。Flash Download Tool 提供了 **CombineBin** 功能，把多个固件合并成**一个 bin**，之后只需烧录一次。

操作步骤：

1. 在 `Download Path Config` 中**按地址**添加所有固件（bootloader、分区表、应用等），并勾选；
2. 设置 **SPI SPEED / SPI MODE**（建议勾选 **DoNotChgBin** 保持固件原始内容）；
3. 点击右下角 **CombineBin** 按钮；
4. 工具自动生成合并文件：**`./combine/target.bin`**（相对工具所在目录）。

合并规则：

- 固件按各自的 Flash 地址放到合并文件中的对应位置；
- 固件之间**空白的区域自动用 `0xFF` 填充**；
- 合并文件大小 ≈ 最后一个固件的结束地址；
- 每次点击 CombineBin 都会**覆盖**上一次的 `target.bin`。

合并完成后，把 `target.bin` 发给任何有 Flash Download Tool 的人，对方只需：

```
地址填 0x0 → 选择 target.bin → START
```

一次烧录完成，全流程无脑可靠。

> 也可以顺手用 `esptool.py` 验证合并结果：`esptool.py --chip esp32 merge_bin -o merged.bin 0x1000 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 firmware.bin`，效果等价。

## 五、常见问题

### Q1：一直提示 "Failed to connect to ESP32"

- 确认芯片已进入下载模式（按住 BOOT + 点按 RST）；
- 确认 COM 口选择正确（可在设备管理器中查看）；
- 换个 USB 线 / USB 口（部分线材只有充电线没有数据线）；
- 降低波特率（115200）重试。

### Q2：烧录成功但设备没反应 / 一直重启

- 确认各 bin 的 Flash 地址是否正确（最常见错误：bootloader 没放 `0x1000`，或 app 没放 `0x10000`）；
- 确认 Flash 大小与固件匹配（如 4MB 芯片刷了 16MB 的分区表）；
- 烧录前先 **Erase** 全片再写入。

### Q3：合并后的 target.bin 无法启动

- 合并前务必确认所有固件都按正确地址添加、且都已勾选；
- 检查 SPI SPEED / SPI MODE 与固件编译参数一致；
- 合并后烧录时起始地址一定要填 `0x0`（不是 `0x1000`）。

### Q4：读取的 bin 比预期小/大

- 读取长度以字节为单位，注意单位换算（`0x400000` = 4MB）；
- 未写入区域读出为 `0xFF` 属正常现象。

## 小结

Flash Download Tools 是乐鑫官方、无需安装、覆盖全系芯片的万能烧录工具，三个核心功能各有用武之地：

| 功能                | 用途                                          |
| ------------------- | --------------------------------------------- |
| **Write 烧录**      | 手动烧录任意 bin，支持地址映射、SPI 参数配置  |
| **Read 提取**       | 备份原厂固件、分析设备内容、救援恢复          |
| **CombineBin 合并** | 多固件打包成一个 bin，批量生产 / 分发一步到位 |

配合官方命令行工具 `esptool.py`，基本可以覆盖 ESP32 开发中所有"和 Flash 打交道"的需求。收藏本文，下次刷机不慌。
